## Setup on a test branch
1. Rotate the previously shared Neon database password. Do not put connection strings in GitHub. Create a Neon development branch and execute `database/001_schema.sql` in SQL Editor on that branch. SQL creates tables only; no sample business rows.
2. Read [SECURITY.md](SECURITY.md). Create a separate restricted runtime role and apply `database/002_runtime_permissions.sql`, verify effective grants. Copy `.env.example` to `.env` locally and set `DATABASE_URL` to its test pooled connection string. Set `ENABLE_TEST_PREVIEW=true` only for synthetic data. Set `ADMIN_DATABASE_URL` locally only for account setup. `python -m venv .venv`, activate it, then `pip install -r requirements.txt`.
3. `python -m database.create_user`; use a unique password. In Neon SQL Editor assign the minimum user permissions using `database/grant_example.sql` as a template. Passwords are hashed; account disabling and access updates apply on the next request. Route permission names here are provisional until original access logic is ported.
4. `python -m unittest discover -s tests -v`; `flask --app api.index run`. Open http://127.0.0.1:5000. No business data is automatically imported; a report can legitimately have zero rows.
5. Vercel: import private GitHub repository, choose Flask framework (or Other if auto-detected), root directory repository root, add DATABASE_URL as a server-side Secret and ENABLE_TEST_PREVIEW=true for an isolated synthetic-data deployment only, deploy. Keep compute close to Neon Ohio (`cle1` if available). Use an authorized plan for business usage (Hobby is personal/non-commercial). Do not promote to production. Test `/api/health` (process status only), login, report permissions and Excel downloads.

## Password resets in Neon SQL Editor
After deploying the bcrypt-compatible backend, authorized database owners can use [database/003_reset_app_password.sql](database/003_reset_app_password.sql) to reset an existing application's password and failed attempts without local Python. Replace both placeholders privately; use 12–72 UTF-8 bytes and avoid the dollar-quote delimiter in the password. This preserves permissions and revokes old sessions. Do not commit filled-in SQL, passwords or password hashes. SQL Editor may retain query history. Existing scrypt accounts remain compatible. A newly created account still requires explicit permissions.

## Architecture and caveats
Same-origin Flask API, short Psycopg connections to Neon pooled endpoint, PostgreSQL permission and session tables, direct binary XLSX response (no Google Drive, base64, or temp file). Larger than 4 MB is rejected with a filter prompt; large-report object storage is not implemented. No persistent background worker. Database row locks, transaction-level idempotency and revision checks must be implemented for operational writes before release. `legacy/Index.html` is unchanged, not a functional standalone UI; `api/index.py` serves an explicitly separate preview page. The proposed schema is not an authoritative mapping of the missing source.
